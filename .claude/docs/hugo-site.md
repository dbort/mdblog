# Hugo site

How the contract in `docs/vault-format.md` maps onto Hugo and the packaged theme. The code is the reference, and its comments give the reason for each mechanism. This file records only what no single file shows, and names the constant, file or test that owns anything code defines instead of copying it.

- **No pass-through.** `front_matter` in `src/mdblog/properties.py` writes each page's Hugo front matter from scratch, so no vault property reaches Hugo. A property named like a Hugo key would otherwise change the site. `test_properties_hugo_would_read_do_not_change_the_site` in `tests/test_build.py` holds the keys known to collide. A Hugo feature wanted later, such as a redirect after a rename, gets its own property.
- **Tags.** Tags ignore case because Hugo lowercases tag paths. `_is_safe_tag_segment` in `properties.py` explains the character rule. A tag holding `page/<number>` can replace a page of a paginated tag listing, and the packaged layouts never paginate tag pages (user decision, 2026-11-04, task-003).
- **Heading links** follow the heading IDs that the build computes to match Hugo's. A heading whose ID Hugo builds from a numeric character reference, such as `&#42;`, can get a different ID, and its link then breaks without failing the build.
- **Site folder.** The bio becomes `content/_index.md`, the home page's content, which the sidebar renders on every page. `SITE_DIRECTORIES` in `src/mdblog/build.py` lists the `_site/` folders copied into the Hugo project, where they override the packaged theme.
- **Theme.** `src/mdblog/theme/layouts/` defines every page and sidebar box. The `*_LIMIT` constants in `build.py` set every list length and reach the layouts as site config, so a test or a site's own layout reads the same value. `home.recent.json` states the `recent.json` contract that pages outside the blog rely on.
- **Draft preview.** `entry-status.html` and `preview-banner.html` draw the labels and banner from Hugo's `.Draft`, the page param `INVALID_PARAM` (`properties.py`) and the site param `PREVIEW_PARAM` (`build.py`). A site's `_site/layouts/` can replace them.
- **Worker bundle.** `src/mdblog/stage.py` moves Hugo's output under the `base_url` path inside a static-assets Worker bundle and generates its wrangler config. Its comments give the reason for the layout and for each generated field.
